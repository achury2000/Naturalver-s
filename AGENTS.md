# NATURALVER'S — Agent Instructions

Next.js 15 (App Router) + Tailwind v3 + Payload CMS 3.26 storefront for natural products.
UI copy is **Spanish**; code identifiers are **English**. `npm` only. No CI, no tests, no formatter.

## Commands

```bash
npm run dev         # next dev (:3000)
npm run build
npm run typecheck   # tsc --noEmit
npm run db:up       # docker compose up -d mongodb
npm run db:down     # docker compose down
npm run seed        # tsx scripts/seed.ts  (wipes + repopulates products/categories/media)
```

- **`npm run lint` does not work.** `eslint` is not in `devDependencies` and there is no eslint config.
  Don't try to fix lint errors you can't reproduce; use `npm run typecheck`.
- **There is no test framework.** No `test` script, no runner, no fixtures. Verification =
  `npm run typecheck` + `npm run dev` + hitting the routes.
- `npm run seed` is **destructive**: it `deleteMany`s on products, categories and media.
- Aliases: `@/*` → `src/*`, and `@payload-config` → `payload.config.ts` (`tsconfig.json`).

## Directory structure

```
src/
  app/
    (payload)/            Payload CMS. Route group = no URL change.
      admin/
        layout.tsx        RootLayout from @payloadcms/next/layouts. Own <html>/<body>.
        importMap.js      GENERATED - never hand-edit.
        [[...segments]]/
          page.tsx        Admin UI. Must stay named "segments" (RootPage reads params.segments).
    (storefront)/         Public site. Own <html>/<body> + globals.css + CartProvider.
      layout.tsx
      globals.css
      providers.tsx
      page.tsx, [slug]/, catalogo/, carrito/, contacto/, ...
    api/
      [[...slug]]/        REST/GraphQL API. Must stay named "slug" (REST handler reads params.slug).
        route.ts
  collections/            Payload collection configs (PascalCase: Products.ts, Media.ts, ...)
  components/
    ui/                   shadcn/ui primitives only. PascalCase (shadcn convention).
    layout/               Site chrome + layout primitives. kebab-case.
    catalog/              Product-listing feature. kebab-case.
    cart/                 Cart feature. kebab-case.
  contexts/              CartContext.tsx ('use client')
  lib/                   payload.ts (data layer), utils.ts (cn helper)
  types/                 index.ts (hand-written) + payload.ts (GENERATED by Payload)
scripts/
  seed.ts
  fixtures/catalog.ts    Seed data ONLY. Never imported from src/.
  make-placeholder.mjs   Regenerates public/placeholder-product.jpg
media/                   Payload upload dir (intentionally NOT gitignored - see below)
public/                  Static assets
```

## Naming conventions

| Location | Convention | Example |
|---|---|---|
| `components/ui/` | **PascalCase** | `Button.tsx`, `Card.tsx` |
| everything else in `components/` | **kebab-case** | `site-layout.tsx`, `product-card.tsx` |
| `collections/` | **PascalCase** | `Products.ts` (Payload convention) |
| `lib/`, `types/` | **kebab-case** | `payload.ts` |

Two root layouts exist by design (Next.js multiple-root-layouts): `(payload)` and `(storefront)`.
They must **never** be nested — `RootLayout` renders its own `<html>`/`<body>`. If you add
`src/app/layout.tsx` you will nest them and break the admin's theming and the storefront's Tailwind.

## Payload CMS wiring

- `payload.config.ts` is the single config instance. It is imported as `@payload-config` by the
  admin layout, the admin page and the API route. **Do not call `buildConfig()` anywhere else** —
  a second instance breaks Payload.
- `buildConfig()` is async: it returns `Promise<SanitizedConfig>`. Don't wrap it in
  `Promise.resolve()`.
- Admin UI is served by `page.tsx`; REST/GraphQL by `route.ts` in `src/app/api`. There is
  deliberately **no** `route.ts` under `(payload)/admin` — `handleEndpoints` always prefixes
  `config.routes.api`.
- `src/app/(payload)/admin/layout.tsx` must keep `import '@payloadcms/next/css'`.
  `RootLayout`'s own `import '@payloadcms/ui/scss/app.scss'` does **not** resolve in the published
  package (only `dist/` ships). Without the explicit CSS import the admin bundle is ~0 bytes and
  renders completely unstyled.
- Regenerate the import map after adding custom admin components:
  `npx payload generate:importmap` (it reads/writes `(payload)/admin/importMap.js`).
- `sharp` is required by `Media.imageSizes` and **must be passed into `buildConfig`** (`sharp,`).
  Installing the package is not enough.
- There is **no email adapter** — Payload logs a warning on boot. The project sends no email yet.
- Regenerate `src/types/payload.ts` with `npx payload generate:types` after changing collections.
- `Orders` access is restricted to `role === 'admin'`.

## Data layer

- `src/lib/payload.ts` is the only data layer. **There is no mock fallback** — the old
  `getMockProducts` / `getMockProductBySlug` / `getMockCategories` shims were deleted along with
  `src/lib/mock-data.ts`. All queries use `depth=2` so upload relations populate.
- `queryProductBySlug` / `queryPageBySlug` return `null` on failure; callers handle it.
- **`await` inside every `try` that wraps `payloadFetch`.** A bare
  `try { return payloadFetch(...) } catch {}` does **not** catch anything — the rejection escapes
  the block and kills `next build`'s prerender with `ECONNREFUSED` whenever the API isn't running.
- The storefront is prerendered at build time but fetches its own API over HTTP, so a plain
  `npm run build` with nothing on `:3000` only succeeds because these helpers degrade to `null`.
  Queries without a `try`/`await` will fail the build.
- `getImageUrl()` falls back to `/placeholder-product.jpg`. That file must exist in `public/`
  (regenerate with `node scripts/make-placeholder.mjs`).

## Known gaps (not bugs — just unfinished)

- **No checkout / payments.** No Stripe, no gateway, no WhatsApp handoff.
  `/pago` renders a "Forma de pago no disponible" placeholder, `/confirmacion` is a static
  thank-you. Neither creates an order. There is **no `NEXT_PUBLIC_WHATSAPP_NUMBER`**; the only
  WhatsApp link is hardcoded in `(storefront)/contacto/page.tsx`.
- **Add-to-cart is not wired.** The button in `components/catalog/product-card.tsx` has no
  `onClick`, and `product-card.tsx` is a plain `div`, not a `next/link`, so products are not
  reachable by URL from the grid.
- **Cart is in-memory only.** `contexts/CartContext.tsx` is plain `useState`: no `localStorage`,
  no DB, resets on reload, never POSTs to `orders`.
- `components/cart/cart-drawer.tsx` is **not rendered anywhere**; `cart-item`, `cart-summary` and
  `quantity-selector` are only reachable through it, so the whole cluster is currently dead.
- ~45 of the 51 files in `components/ui/` are unused shadcn primitives, kept as a library. Re-add
  any of them with `npx shadcn@latest add <name>`.
- The admin UI renders in **English** (`lang="en"`). Set `admin.i18n` to change it.

## Routing

`src/app/(storefront)/[slug]/page.tsx` resolves a slug as **product first, CMS page second**
(`queryProductBySlug` → `queryPageBySlug` → `notFound()`), and runs `generateMetadata`.
Static segments (`/catalogo`, `/nosotros`, `/blog`, …) take precedence over it.

`components/layout/site-layout.tsx` applies `pt-16` to offset the `fixed` header, but the header is
`h-[57px]` — there is a 7px gap. Add fixed-header content inside that component's `<main>`, not in
the route's root layout.

## Design tokens are defined twice — keep them in sync

Brand colors exist in **both** `tailwind.config.ts` (`brand.dark/light/navy/sky`) and
`src/app/(storefront)/globals.css` (`--color-brand-*`). Adding or renaming a color means editing
both. Use `text-brand-dark` / `bg-brand-light` rather than raw hex.

Fonts: `font-heading` (Lora), `font-body` (Raleway), `font-script` (Great Vibes) — loaded via a raw
Google Fonts `<link>` in `(storefront)/layout.tsx`, not `next/font`. `components/layout/header.tsx`
also uses `font-inter`, which is **not** defined in the Tailwind theme and silently does nothing.

`darkMode: 'class'` is configured but no dark theme is implemented.

## Environment

`payload.config.ts` has dev fallbacks (`PAYLOAD_SECRET=dev-secret-change-me`,
`mongodb://localhost:27017/naturalvers`), so `npm run dev` and `npm run build` work with no env
file. `.env.local` is gitignored and **not present** — create it from `.env.example` when you need
real values. `NEXT_PUBLIC_PAYLOAD_API_URL` (read by `src/lib/payload.ts`) defaults to `/api`.

`serverURL` defaults to `http://localhost:3000`. If dev runs on a different port (because 3000 is
occupied) Payload-generated absolute URLs — e.g. the `action` on the create-first-user form — will
point at the wrong port. Set `NEXT_PUBLIC_SITE_URL` to match.

## Other traps

- **`media/` must stay versioned.** `npm run seed` writes Media rows whose `filename` points at
  files in `media/`. Ignoring that directory reproduces
  `File ... for collection media is missing on the disk` + 500s on a fresh clone. If you ever
  ignore it, make the seed download or generate its images instead.
- `next.config.js` allows `next/image` remote sources only for `placehold.co` and
  `res.cloudinary.com`. Any other host needs a new `remotePatterns` entry.
- Most components are Server Components; add `'use client'` only for state/handlers
  (`header.tsx`, `search-bar.tsx`, `product-sort.tsx` are client).
- **React must stay on 19.** `@payloadcms/ui@3.26.0` declares `react: ^19.0.0` and Payload's
  `checkDependencies()` throws at boot on React 18, which silently breaks the admin.
