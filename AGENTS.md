# NATURALVER'S — Agent Instructions

Next.js 15 (App Router) + Tailwind v3 + Payload CMS 3.26 storefront for natural products.
UI copy is **Spanish**; code identifiers are **English**. `npm` only. No CI, no tests, no formatter.

## Commands

```bash
npm run dev         # next dev (:3000)
npm run build       # verified: succeeds with NO mongo and NO dev server running
npm run typecheck   # tsc --noEmit - currently passes with 0 errors
npm run db:up       # docker compose up -d mongodb  (container: naturalvers-mongodb)
npm run db:down     # docker compose down
npm run seed        # tsx scripts/seed.ts  (wipes + repopulates products/categories/media)
```

- **Never run `npm run lint`.** `eslint` is not in `devDependencies` and there is no eslint config,
  so `next lint` drops into an **interactive** ESLint-setup prompt and hangs. Verification =
  `npm run typecheck` + `npm run dev` + hitting the routes.
- **There is no test framework.** No `test` script, no runner, no fixtures.
- Aliases: `@/*` → `src/*`, `@payload-config` → `payload.config.ts` (`tsconfig.json`).

## Naming conventions

| Location | Convention | Example |
|---|---|---|
| `components/ui/` | **PascalCase** | `Button.tsx`, `Card.tsx` |
| everything else in `components/` | **kebab-case** | `site-layout.tsx`, `product-card.tsx` |
| `collections/` | **PascalCase** | `Products.ts` (Payload convention) |
| `lib/`, `types/` | **kebab-case** | `payload.ts` |

Two root layouts exist by design (Next.js multiple-root-layouts): `(payload)` and `(storefront)`.
They must **never** be nested — `RootLayout` renders its own `<html>`/`<body>`. Adding
`src/app/layout.tsx` would nest them and break the admin's theming and the storefront's Tailwind.

## Payload CMS wiring

- `payload.config.ts` is the single config instance, imported as `@payload-config` by the admin
  layout, the admin page and the API route. **Never call `buildConfig()` elsewhere** — a second
  instance breaks Payload. `buildConfig()` is sync-returning here; do not wrap it.
- **Only REST is served.** `src/app/api/[[...slug]]/route.ts` wires GET/POST/PUT/PATCH/DELETE/OPTIONS
  and nothing else — there is **no GraphQL handler** and no `graphql` config. `graphql` is a
  transitive Payload dependency, not a feature here.
- There is deliberately **no** `route.ts` under `(payload)/admin` — `handleEndpoints` always
  prefixes `config.routes.api`.
- `src/app/(payload)/admin/layout.tsx` must keep `import '@payloadcms/next/css'`.
  `RootLayout`'s own `import '@payloadcms/ui/scss/app.scss'` does **not** resolve in the published
  package (only `dist/` ships). Without the explicit import the admin renders unstyled.
- `importMap.js` is currently an empty `{}` — no custom admin components yet. After adding one:
  `npx payload generate:importmap`.
- After changing any collection: `npx payload generate:types` (output path comes from
  `typescript.outputFile` in `payload.config.ts` → `src/types/payload.ts`).
- `sharp` powers `Media.imageSizes` and **must stay passed into `buildConfig`** (`sharp,`).
  Installing the package is not enough.
- **No email adapter** — Payload logs a warning on boot. `.env.example` lists `EMAIL_*` vars but
  nothing reads them.
- **Access control is uneven.** Only `Orders` gates on `role === 'admin'` (create is open to
  anyone, by design — the storefront submits orders anonymously). `Users` has **no** `access`
  block, so *any* authenticated user can log into `/admin`. Tightening this is a real gap.
- Admin UI renders in **English** (`lang="en"`); there is no `admin.i18n`. Set it to change.

## Data layer

`src/lib/payload.ts` is the only server data layer. **There is no mock fallback** — the old
`getMock*` shims and `src/lib/mock-data.ts` were deleted.

- **Only `queryPageBySlug` catches errors and returns `null`.** `queryProducts`,
  `queryCategories` and `queryProductBySlug` **throw**. This is exactly why `npm run build`
  survives with no API running: no statically-prerendered page calls the throwing helpers.
  - `GET /`, `/nosotros`, `/blog`, `/contacto`, `/cuenta`, `/carrito`, `/pago`, `/confirmacion`
    are static and touch nothing.
  - `GET /devolver`, `/envios`, `/preguntas`, `/privacidad`, `/terminos` are CMS-driven via
    `queryPageBySlug` (the null-safe one). They degrade to a "not available" state.
  - `/catalogo`, `/busqueda`, `/[slug]` are dynamic (`ƒ`) — they render per-request and will
    surface a thrown query as a 500 in dev.
- **Adding a static page that calls `queryProducts` will break `npm run build`** with
  `ECONNREFUSED` unless the API is up. Either use `queryPageBySlug` or wrap the call in
  `try { await … } catch`. A bare `try { return payloadFetch(…) } catch {}` catches nothing.
- `getPayloadApiUrl()` falls back to `headers()` for absolute URLs; with
  `NEXT_PUBLIC_PAYLOAD_API_URL=/api` this opts any calling route into dynamic rendering.
- `getImageUrl()` (re-exported from `lib/media.ts`) falls back to `/placeholder-product.jpg`.
  That file must exist in `public/`.
- `src/types/index.ts` is **dead** — nothing imports it and every query returns `any`. Don't trust
  it as a contract; use the generated `src/types/payload.ts` types instead.

## Cart & checkout (wired — don't assume it's missing)

- Cart is browser-only in `localStorage` under key **`naturalvers-cart`**, restored in a
  `useEffect` after mount. The context exposes **`hydrated`**; gate any badge/count render on it
  (`hydrated && totalItems > 0`) or you reintroduce a hydration mismatch.
- All totals funnel through `src/lib/commerce.ts` — free shipping at **COP 100 000**, otherwise
  **COP 15 000**. Header badge, drawer, `/carrito` and `/pago` all read the same numbers. Change
  prices there, not per component.
- `src/lib/order-actions.ts` is a `'use server'` module. `submitCheckout`:
  re-reads every product from the catalog (`depth: 0`) and **discards browser-supplied prices**,
  clamps quantity to live stock, generates `NV-YYMMDD-XXXX`, and retries up to 3× on the unique
  index. Never trust client-sent prices when touching this path.
- WhatsApp hand-off: `getWhatsappNumber()` reads `NEXT_PUBLIC_WHATSAPP_NUMBER` (digits only, no
  `+`). `/pago` opens the tab **before** awaiting the server action to dodge the popup blocker,
  then closes it if the order fails. If the number is unset the order is still stored and the
  customer is told contact is unavailable. `/contacto` uses the same helper — no hardcoded number
  remains anywhere.
- `/confirmacion` reads the order number from the `?orden=` query param via `useSearchParams`
  (wrapped in `Suspense`) and does not re-fetch the order.

## Routing

- `src/app/(storefront)/[slug]/page.tsx` resolves **product first, CMS page second**
  (`queryProductBySlug` → `queryPageBySlug` → `notFound()`) and runs `generateMetadata`.
  Static segments (`/catalogo`, `/nosotros`, `/busqueda`, …) take precedence.
- `components/layout/site-layout.tsx` exports `Layout` (named). It renders `Header`, `Footer` and
  **`CartDrawer`**, and applies `pt-16` to offset the `fixed` header — but the header is
  `h-[57px]`, leaving a 7px gap. Add fixed-header content inside that component's `<main>`, not in
  a route's root layout.
- Known rough edge: `catalogo/page.tsx` is a Server Component but passes `onClick` to the
  "Limpiar filtros" button. Verify in the browser before relying on that control.

## Design tokens are defined twice — keep them in sync

Brand colors exist in **both** `tailwind.config.ts` (`brand.dark/light/navy/sky`) and
`src/app/(storefront)/globals.css` (`--color-brand-*`, currently declared but unused by any
component). Adding or renaming a color means editing both. Prefer `text-brand-dark` /
`bg-brand-light` over raw hex.

Fonts are currently **`font-heading` (Lora), `font-body` (Raleway), `font-script` (Great Vibes)**,
loaded via a raw Google Fonts `<link>` in `(storefront)/layout.tsx`, not `next/font`. Plus:

- `header.tsx` applies `font-inter` to its four nav links; `font-inter` is **not** in the Tailwind
  theme and silently does nothing.
- `darkMode: 'class'` is configured but no dark theme exists.
- Single logo source of truth: `src/components/layout/logo.tsx` (renders `public/logo.png`,
  1063×195 intrinsic ratio, `size="sm"|"md"`, `priority` only in the header).
- `next.config.js` allows `next/image` from `placehold.co`, `res.cloudinary.com`, and
  `/api/media/**` on `localhost`/`127.0.0.1`/`NEXT_PUBLIC_SITE_URL`'s host. Any other host needs
  a new `remotePatterns` entry.

## Environment

`payload.config.ts` has dev fallbacks (`PAYLOAD_SECRET=dev-secret-change-me`,
`mongodb://localhost:27017/naturalvers`), so `npm run dev` / `npm run build` work with no env file.
`.env.local` **is present and gitignored** — `next build` reports `- Environments: .env.local`, so
build-time behavior depends on it. `.env.example` is the template. Copy from it, don't hand-roll.

`serverURL` defaults to `http://localhost:3000`. If dev runs on a different port (3000 occupied),
Payload-generated absolute URLs — e.g. the `action` on the create-first-user form — point at the
wrong port. Set `NEXT_PUBLIC_SITE_URL` to match.

## Seed & media

- **`npm run seed` is destructive**: it `deleteMany`s products, categories and media.
- It talks to MongoDB through the raw `mongodb` driver, **not** through Payload — no hooks, no
  access control, no field validation, and it writes `_id: ObjectId` docs directly.
- **`media/` must stay versioned.** Seed sets each media doc's `filename` to `<slug>.jpg`, which
  Payload resolves to `media/<slug>.jpg`. The 6 committed jpgs are what make those rows valid;
  ignoring the directory reproduces `File … for collection media is missing on the disk` + 500s on
  a fresh clone. Nothing regenerates them — `scripts/make-placeholder.mjs` only writes
  `public/placeholder-product.jpg`.

## Server vs client components

Most components are Server Components. `'use client'` is required only for state, handlers or
context — currently `header.tsx`, `product-card.tsx`, `search-bar.tsx`, `product-sort.tsx`,
`category-filter.tsx`, `add-to-cart-panel.tsx`, `cart-view.tsx`, `checkout-form.tsx`,
`order-confirmation.tsx`, `cart-drawer.tsx`, `providers.tsx`, `CartContext.tsx`.
~41 of the 43 files in `components/ui/` are unused shadcn primitives kept as a library; re-add any
with `npx shadcn@latest add <name>`.

- **React must stay on 19.** `@payloadcms/ui@3.26.0` declares `react: ^19.0.0` and Payload's
  `checkDependencies()` throws at boot on React 18, which silently breaks the admin.
